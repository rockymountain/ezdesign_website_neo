# Business Model Canvas

# EZD AI Chat — Friction Intelligence System

## Định vị cốt lõi

```txt
EZD AI Chat không bán chatbot.

EZD AI Chat bán một hệ thống phát hiện, giải mã và xử lý những ma sát vô hình khiến khách hàng chưa mua.
```

Phiên bản nội bộ:

```txt
We do not optimize chat.
We optimize friction-to-conversion.
```

EZD AI Chat là một **Data-Driven Conversion Engine** cho SME B2C. Widget chat chỉ là lớp giao diện. Tài sản thật của hệ thống là dữ liệu hội thoại đã được chuẩn hóa thành **Verified Friction-to-Conversion Patterns**.

# 1. Customer Segments

## Nhóm khách hàng chính

EZD AI Chat phục vụ **SMEs B2C trong các ngành có ma sát mua hàng cao**, tức là khách hàng thường cần hỏi, cân nhắc, so sánh, được trấn an hoặc được tư vấn trước khi ra quyết định.

Các vertical ưu tiên:

```txt
1. Hospitality
   Homestay, retreat, villa, boutique stay, cafe-retreat.

2. Services
   Agency, design, branding, website, studio, photography.

3. Education
   Trung tâm ngoại ngữ, trường tư thục, lớp kỹ năng, đào tạo nghề.

4. Wellness / Beauty / Clinic
   Spa, salon, clinic, thẩm mỹ, chăm sóc sức khỏe.

5. Local Booking Services
   Các dịch vụ đặt lịch, đặt hẹn, tư vấn cá nhân hóa.
```

## Đặc điểm chung của khách hàng mục tiêu

```txt
- Có lượng câu hỏi lặp lại cao.
- Có quy trình lead / booking / consultation rõ ràng.
- Mỗi lead có giá trị đủ lớn.
- Chủ doanh nghiệp thiếu đội tư vấn chuyên nghiệp.
- Khách hàng cuối thường có nhiều nỗi lo trước khi mua.
- Thương hiệu cần giữ giọng nói và trải nghiệm nhất quán.
```

## Reference tenants ban đầu

```txt
- Yên Retreat: Hospitality / Retreat.
- EZDesign: Services / Design / Website / Branding.
- Việt Anh: Education.
```

# 2. Value Propositions

## Cho SME B2C

EZD AI Chat cung cấp một **AI Brand Receptionist** hoạt động 24/7, không chỉ trả lời FAQ mà còn giúp phát hiện và xử lý các rào cản khiến khách chưa mua.

Giá trị chính:

```txt
- Không bỏ lỡ khách hàng ngoài giờ làm việc.
- Tư vấn nhất quán theo giọng thương hiệu.
- Tự động xử lý các câu hỏi, lo ngại và từ chối phổ biến.
- Tăng khả năng chuyển khách từ tò mò sang lead.
- Giúp chủ doanh nghiệp hiểu vì sao khách rời đi.
- Giảm phụ thuộc vào nhân sự tư vấn thủ công.
```

Nói ngắn gọn:

```txt
SME không mua chatbot.
SME mua khả năng giảm ma sát mua hàng.
```

## Cho EZD

EZD tích lũy một tài sản chiến lược:

```txt
Verified Friction-to-Conversion Pattern Library
```

Đây là thư viện các pattern đã được xác thực về:

```txt
- Khách hàng bị kẹt ở đâu.
- Họ lo sợ điều gì.
- Họ chưa tin điều gì.
- Response angle nào giúp họ tiếp tục hội thoại.
- Response angle nào tạo lead, booking hoặc handoff tốt hơn.
```

Về dài hạn, EZD sở hữu:

```txt
The Multi-Vertical Friction Map
```

Tức là bản đồ ma sát chuyển đổi của nhiều ngành SME B2C.

# 3. Channels

## Kênh triển khai chính

```txt
Embedded Website Widget
```

Widget là điểm chạm chính để thu thập tín hiệu thị trường và hỗ trợ khách hàng cuối ngay trên website của tenant.

## Kênh mở rộng

```txt
- Landing page ngành trên ezdesign.vn / EZD AI Chat.
- Zalo handoff.
- WhatsApp / Messenger / Instagram DM trong tương lai.
- CRM dashboard hoặc mini-dashboard cho chủ doanh nghiệp.
- QR tại cửa hàng, lễ tân, quầy tư vấn.
- Website/landing page do agency hoặc EZD triển khai cho khách.
```

## Vai trò chiến lược của Channel

Website widget không chỉ là kênh support. Nó là **sensor** đặt tại điểm chạm khách hàng để ghi nhận:

```txt
Intent → Friction → Response → Outcome
```

# 4. Customer Relationships

## Tier 1 — Self-service / Low-touch

Khách hàng có thể triển khai widget với chi phí thấp, cấu hình cơ bản và tài liệu hướng dẫn.

Phù hợp với:

```txt
- SME nhỏ.
- Tenant thử nghiệm.
- Khách cần AI receptionist cơ bản.
```

## Tier 2 — Guided Growth

EZD đồng hành tối ưu hiệu quả chuyển đổi.

Bao gồm:

```txt
- Review dữ liệu hội thoại.
- Báo cáo friction.
- Gợi ý sửa FAQ, landing page, offer.
- Tối ưu response angle.
- Cải thiện lead flow.
```

## Tier 3 — Strategic Intelligence Partnership

Khách hàng sử dụng EZD như đối tác tăng trưởng dựa trên dữ liệu.

Bao gồm:

```txt
- Vertical playbook.
- Conversion audit.
- Response A/B testing.
- AI character / knowledge base đã tối ưu theo ngành.
```

## Data Rights & Trust

Đây là quan hệ niềm tin cốt lõi.

```txt
- Raw conversation thuộc phạm vi tenant.
- PII và lead data chỉ dùng để phục vụ tenant đó.
- EZD không bán dữ liệu thô.
- EZD không tiết lộ dữ liệu riêng hoặc performance riêng của tenant.
- EZD chỉ sử dụng pattern đã ẩn danh, chuẩn hóa và tổng hợp để cải thiện hệ thống.
- Tenant được hưởng lợi từ vertical intelligence đã tổng hợp.
```

## Owner Feedback Loop

EZD cần vòng lặp phản hồi từ chủ doanh nghiệp để xác thực chất lượng lead.

Ví dụ trạng thái lead:

```txt
- booked
- lost
- pending
- spam
- high-quality
- low-quality
```

Vòng lặp này giúp hệ thống học từ kết quả kinh doanh thật, không chỉ từ hành vi trong widget.

# 6. Key Resources

## 1. Friction Object Data Model

Đơn vị dữ liệu nguyên thủy của EZD AI Chat.

```txt
Context → Intent → Friction → Response Angle → Customer Reaction → Outcome
```

Ví dụ cấu trúc:

```json
{
  "vertical": "education",
  "stage": "tuition_inquiry",
  "intent": "ask_about_course_for_child",
  "frictionCategory": "outcome_anxiety",
  "rawSignal": "Con mất gốc có học được không?",
  "normalizedObjection": "child_level_fit",
  "responseAngle": "placement_test_and_personalized_roadmap",
  "customerReaction": "asked_for_schedule",
  "outcomeProxy": "lead_flow_completed",
  "confidence": 0.82,
  "privacyLevel": "anonymized_vertical_pattern"
}
```

## 2. Verified Pattern Library

Thư viện các pattern đã được xác thực bằng outcome signal.

```txt
Verified Pattern = Friction Category + Response Angle + Outcome Signal + Minimum Sample Size
```

Đây là tài sản lõi của EZD.

## 3. Objection / Friction Taxonomy

Bộ phân loại rào cản theo từng vertical.

Ví dụ:

```txt
Hospitality:
- location_concern
- privacy_concern
- weather_uncertainty
- package_clarity
- group_fit
- amenity_expectation

Education:
- outcome_anxiety
- child_level_fit
- teacher_trust
- schedule_fit
- tuition_justification
- commitment_concern

Services / Agency:
- price_uncertainty
- scope_ambiguity
- timeline_concern
- trust_in_capability
- ROI_expectation
- freelancer_comparison
```

## 4. Privacy-safe Intelligence Pipeline

Đường ống biến dữ liệu hội thoại thành tri thức ngành mà không làm lộ dữ liệu riêng.

```txt
Raw Conversation
→ Sanitized Signal
→ Friction Object
→ Anonymized Vertical Pattern
→ Verified Pattern Library
→ Vertical Playbook / AI Template
```

## 5. Gateway & Backend Architecture

Hạ tầng kỹ thuật hiện tại là nền tảng để scale chi phí thấp:

```txt
Customer website
→ EZD Chat Widget
→ Cloudflare Worker Gateway
→ R2 tenant registry/config/assets
→ Cloud Run AI Backend
→ Gemini
```

Kiến trúc này giúp EZD:

```txt
- Giữ core code generic.
- Tách tenant data khỏi source tree.
- Kiểm soát public/private boundary.
- Giảm OpEx.
- Mở rộng multi-tenant dễ hơn.
```

# 7. Key Activities

## 1. Extraction & Tagging

Chiết xuất tín hiệu từ hội thoại raw thành các trường có cấu trúc:

```txt
- intent
- friction
- objection category
- response angle
- customer reaction
- outcome proxy
```

## 2. Outcome Attribution

Gắn mỗi Friction Object với tín hiệu kết quả.

Các cấp attribution:

```txt
Level 1 — Proxy Signals:
- Zalo click
- call click
- lead flow completed
- booking inquiry
- return session
- continued conversation after price

Level 2 — Owner Feedback:
- booked
- lost
- pending
- spam
- high-quality lead
- low-quality lead

Level 3 — System Integration:
- CRM
- POS
- booking system
- Google Sheets / Airtable / Notion
- webhook từ form hoặc calendar
```

## 3. Response R&D

Thử nghiệm nhiều response angle cho cùng một friction category.

Mục tiêu:

```txt
Tìm Winning Script theo từng vertical.
```

Ví dụ:

```txt
Friction: “Giá cao”
Response Angle A: giải thích chi tiết chi phí
Response Angle B: đóng gói theo giá trị nhận được
Response Angle C: so sánh với rủi ro khi chọn sai
Response Angle D: đưa lựa chọn entry-level
```

Sau đó đo outcome để xác định angle nào hiệu quả hơn.

## 4. Taxonomy Governance

Quản trị danh mục friction để dữ liệu không bị loạn khi scale.

Hoạt động gồm:

```txt
- Chuẩn hóa category theo vertical.
- Mapping raw objection vào normalized category.
- Merge category trùng lặp.
- Split category quá rộng.
- Tạo global taxonomy cho friction phổ quát.
- Định kỳ review taxonomy dựa trên dữ liệu mới.
```

## 5. Vertical Taxonomy Validation

Mỗi tenant mới không chỉ là khách hàng mới, mà là cơ hội kiểm chứng taxonomy.

Sprint 8 và 9 nên được hiểu là:

```txt
Sprint 8:
Add EZDesign Tenant + Validate Service-Business Friction Taxonomy.

Sprint 9:
Add Việt Anh Tenants + Validate Education Friction Taxonomy.
```

## 6. Playbook Packaging

Chuyển verified patterns thành sản phẩm thương mại:

```txt
- Vertical Playbook.
- Knowledge Base Template.
- AI Character Template.
- Response Script Library.
- Conversion Report.
```

# 10. North Star Metric

## Chỉ số sao Bắc Đẩu

```txt
Verified Friction-to-Conversion Patterns per Vertical
```

Công thức:

```txt
Verified Patterns_vertical
= Σ(Friction Category + Response Angle + Outcome Signal)
  với sample size ≥ N
```

Một pattern chỉ được coi là verified khi có đủ:

```txt
- Friction category rõ ràng.
- Response angle rõ ràng.
- Outcome signal đủ tin cậy.
- Sample size tối thiểu.
- Không vi phạm privacy.
```

## Vì sao metric này quan trọng?

Các metric như số tenant, số message, số lượt mở widget, số lead chỉ là operational metrics.

North Star Metric phải đo tài sản dài hạn:

```txt
Hệ thống đã học được bao nhiêu cách giảm ma sát mua hàng có thể tái sử dụng theo ngành?
```
